## v1.7.1 — `mediagraph watch` discoverability in SKILL.md

Documentation patch for `mediagraph watch` (shipped in 1.7.0). No code changes.

Before: a single dense table row alongside ten other commands; no worked examples; the canonical bulk-tag workflow used polling.

Now in `mediagraph skill` (and `release-notes/v1.7.1.md` here):

- A dedicated **"Watching long-running jobs"** section with a per-type table and three worked examples (bulk job, image upload, video transcode).
- Explicit **`watch` vs `--wait` guidance** — `watch` for live progress, `--wait` to block until done and return only the final state.
- Workflow examples updated to use `watch` end-to-end:

  ```bash
  guid=$(mediagraph create_bulk_job --asset_ids 12,34,56 --tag_names sunset --tag_mode add | jq -r .guid)
  mediagraph watch bulk_job "$guid"   # streams progress=0/20/40/.../100, exits at done
  ```
- The bulk-jobs capability paragraph cross-references the watch section.

### Known gap

`mediagraph search-tools watch` still returns `[]` because `watch` is a top-level builtin command (alongside `serve`, `auth`, `sync`), not a registered tool. Agents discovering via `search-tools` keyword search won't hit it directly — they'll find it via `mediagraph skill` instead. A future patch may extend `search-tools` to index builtin commands.
