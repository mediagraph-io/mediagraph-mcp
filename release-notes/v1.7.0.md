## v1.7.0 — `mediagraph watch`

Real-time progress streaming for long-running jobs. Tries an ActionCable WebSocket subscription first (low-latency push from the server), falls back to polling on any failure. Each event prints as a JSON line on stdout — pipeable into `jq`, `tee`, etc.

### New command

```bash
mediagraph watch <type> <id> [--timeout SEC] [--poll-only|--ws-only] [--poll-interval SEC]
```

Supported types and their terminal predicates:

| Type | Cable channel | Polling endpoint | Polled terminal |
| --- | --- | --- | --- |
| `bulk_job <guid>` | `UserChannel` (filtered by guid) | `getBulkJob` | `aasm_state ∈ {processed, errored, canceled}` |
| `upload <id>` | `UploadChannel` | `getUpload` | `done_at` set or `aasm_state=cancelled` |
| `asset <id>` | `UserChannel` (filtered by asset_id) | `getAsset` | `head.aasm_state ∈ {processed, processing_error}` |
| `meta_import <id>` | `UserChannel` | `getMetaImport` | `aasm_state ∈ {processed, errored}` |
| `tag_import <id>` | `UserChannel` | `getTagImport` | `aasm_state ∈ {processed, errored}` |
| `ingestion <id>` | `UserChannel` | `getIngestion` | `aasm_state ∈ {processed, canceled, errored}` |
| `share <id>` | `SharesChannel` | `getShareStatus` | `progress=100` or `code`/`url` set |
| `bulk_upload <guid>` | `BulkUploadsChannel` | `getBulkUploadStatus` | `aasm_state ∈ {completed, cancelled, errored}` |
| `meta_download <id>` | `UserChannel` | `getMetaDownload` | `aasm_state ∈ {processed, errored}` or `file_url` set |

Adding more types is a 5-line config addition in `src/cli/watch.ts`.

### Auth bridge

ActionCable expects a Devise JWT, but the CLI authenticates via OAuth Bearer / PAT. The new `client.refreshJwt()` mints a JWT from the existing OAuth token via `POST /api/refresh` and feeds it to the WS connection (`?token=…&organization_id=…`).

### Polling fallback

Any WS failure (connection, auth rejection, mid-stream disconnect, timeout) falls back to polling the REST endpoint at `--poll-interval` (default 2s). Each fallback emits a `meta` line on stderr with the reason. `--poll-only` skips the WS attempt entirely; `--ws-only` makes the WS path mandatory and surfaces a `NETWORK` error if it fails.

### Output contract

- **stdout** — JSON-line stream of events. Each line is a single JSON object with `type`, `id`, and the broadcast payload (or polled snapshot) merged in.
- **stderr** — optional `{meta: ...}` lines for connection notes (e.g. WS-to-polling fallback).
- **exit code** — 0 on terminal state reached, 1 on timeout / network, 2 on bad args.

### New client methods (back the polling fallbacks)

`refreshJwt`, `getIngestion`, `cancelIngestion`, `listBulkUploads`, `getBulkUpload`, `getBulkUploadStatus`, `getBulkUploadExistingAssets`, `getMetaDownload`.

### Release tooling

`scripts/release.sh` now requires a hand-written `release-notes/v<version>.md` file before bumping (so the GitHub release page always carries a real changelog), and posts that file to the GitHub release via `gh release` after pushing the tag. Falls through to `gh release edit` when the Actions workflow creates the release first.
